# АСКУЭ базы на ул. Кардачинская, 28

Технический учёт электроэнергии на базе ООО «РегионСтройСистемы» (Красноярск).
Система раз в минуту опрашивает счётчики, хранит показания, показывает графики
и присылает в Telegram вечерний отчёт о невыключенных объектах.

## Оборудование

| Шкаф | Шлюз USR-DR302 | Адрес | Счётчики (Modbus-адрес) |
|---|---|---|---|
| ША1 (у ВРУ базы) | GW1, MAC 38-F4-06-0D-E6-51 | 192.168.12.200:20108 | M1 WB-MAP12E (11), M2 WB-MAP3E (12) |
| ША2 (Склад 2) | GW2, MAC 38-F4-06-0D-E6-63 | 192.168.14.200:20108 | M3 WB-MAP3E (21), M4 WB-MAP3E (22) |

Линия RS-485 каждого шлюза: 9600 бит/с, 8 бит, без чётности, 2 стоп-бита. Шлюз работает
в режиме TCP Server, прозрачно (Modbus RTU поверх TCP). Подсети 192.168.12.x и 192.168.14.x —
сети видеонаблюдения, их обслуживает Игорь Сапронов.

Точки учёта и их названия — в [config/config.yaml](config/config.yaml).

## Устройство

```
счётчики --RS-485--> шлюзы --TCP 20108--> poller --> PostgreSQL --> Grafana (порт 3000)
                                                         \--> bot --> Telegram (@askuerssbot)
```

**Точки и объекты.** Точки — каналы счётчиков (что измеряется). Объекты — то, за чем следят люди;
они складываются из точек (`objects` в config.yaml): Склад 2 = линия на ВРУ «Склад 2 + Склад 3» − M3 − M4,
3 ангар = M3, Сервис 777 = M4 (с 25.11.2026), «Вся база» = сумма всех вводов. Отрицательные значения разности показываются как 0.

**Опрос** (замер 23.11.2026: запрос P через шлюз 44 мс, P по 5 каналам ША1 — 0,22 с, полный набор — 1,03 с;
счётчик обновляет P чаще, чем его можно прочитать, — предел задаёт линия RS-485 9600 бит/с):
- мощность P (total и по фазам) каждые 2 с → `power_fast`, хранится 14 дней;
- минутные средняя/мин/макс → `power_1m`, хранятся всегда;
- раз в минуту полный набор (U, I, cos, энергия приём/отдача) → `readings`.

**Энергия за период** считается по показаниям счётчиков энергии (как у энергосбыта), поэтому
не зависит от пропусков опроса и от ошибочной энергии, накопленной до запуска системы.

- `app/askue/poller.py` — опрос (только чтение, функция Modbus 04), поток на каждый шлюз.
- `app/askue/bot.py` — бот: транспорт Telegram, расписание (вечерний отчёт: админам полный, охране — только
  «не выключенные»; утренняя сводка админам), предупреждения (объект выше ночного порога, нет связи, растёт отдача).
- `app/askue/dialog.py` — пошаговый диалог в одном сообщении: **Меню → ⚡ Мощность / 🔋 Энергия → объект(ы)
  с галочками → период → ответ с кнопками уточнения**. Мощность: сейчас (10 с, по фазам, мин/макс за минуту),
  15 мин (2-с точки), 3/12/24 ч (средние 1/5/10 мин, у одного объекта — полоса мин–макс). Энергия: сегодня,
  вчера, 7 дней, месяц, прошлый месяц, свой период (ввод «01.11–15.11»); ответ числом с показаниями
  счётчиков, затем график нарастающим итогом или по часам/дням. Охране доступны мощность и сводка.
- `app/askue/query.py` — выборки для диалога; `app/askue/report.py` — тексты отчётов;
  `app/askue/charts.py` — графики PNG; `scripts/test_dialog.py` — прогон всех веток диалога без отправки.
- `grafana/` — страницы «Объекты» (`/d/askue-main`) и «Техника» (`/d/askue-tech`).
- Сервис `backup` раз в сутки делает дамп базы в `backups/`, хранит 30 дней.

**Шлюз держит одно TCP-подключение**: новое выбивает старое. Пока работает опросчик, не подключаться
к шлюзам с других компьютеров — пропадут точки. Диагностику запускать на виртуалке, остановив poller.

## Развёртывание

Работает с 23.11.2026 на виртуалке **192.168.107.10** (hostname 3s-iot, Ubuntu 24.04, выдал
И. Сапронов), пользователь `admin3s`, вход по ключу `askue_ed25519` с 3S-WS03, sudo без пароля.
Код лежит в `~/askue-baza` (рабочая копия git, принимает push напрямую), секреты — в `~/askue-baza/.env`.

- Дашборд: **http://192.168.107.10:3000** (просмотр без входа; вход admin — пароль в `.env`).
- Обновление с 3S-WS03: `powershell -File scripts\deploy.ps1` — push в GitHub и на виртуалку, пересборка.
- Бот @askuerssbot работает. Новый чат: написать в нём боту `/id` (id попадёт и в журнал бота),
  вписать в `.env`: админов — в `TELEGRAM_CHAT_IDS`, охрану — в `TELEGRAM_GUARD_IDS`; `docker compose up -d`.

Новая виртуалка с нуля: `scripts/vm_setup.sh` (Docker, клон с GitHub, `.env`).

Проверка опроса без базы (на любом компьютере с доступом к шлюзам):

```
cd app
python -m askue.poller --once --dry-run --config ../config/config.yaml
```

На 3S-WS03 работает VPN, поэтому там нужно `MODBUS_SOURCE_IP=192.168.105.101`.

## Правила

- Опрашивать счётчики должен только один опросчик. ЛЭРС или другой опрос параллельно не включать:
  запросы на линии RS-485 будут сталкиваться.
- Программа только читает счётчики. Запись настроек (числа ТТ) делается отдельно и только по
  решению С. В. Фролкова.
- Шлюзы не открывать в интернет: Modbus без шифрования и пароля.
- Секреты только в `.env` на сервере.
